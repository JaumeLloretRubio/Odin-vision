# Prueba con otro vídeo — 14 de septiembre de 2026

La aceptación funcional ha pasado con modelos reales en GPU y un servidor Uvicorn accesible por TCP
local. Reutiliza `scripts.lab_stream.run_stream`, el mismo flujo de la v1: vídeo a su cadencia original,
descarte de frames atrasados, etiquetado durante el WebSocket y reconocimiento en una sesión nueva.
Se añade reapertura de la aplicación y SQLite, conservando los pesos cargados.

Vídeo: `traffic.webm`, tráfico urbano, 1920×1080, 30 FPS, 534 frames declarados (17,8 s).
La decodificación del streaming leyó 532 frames por recorrido. Se envió JPEG a 960×540, categoría `car`,
con descripciones y grabación activadas. La v1 probó su streaming con `pedestrians.webm`;
el vídeo de tráfico ya estaba en el material de laboratorio, pero es distinto de ese ensayo.

- Cero errores de API en los tres recorridos; 1.367 frames procesados en total.
- Etiqueta creada en el frame 5, HTTP 201, cinco ejemplos. Descripción: “a white car driving down a street”.
- Dos clips de las dos primeras fases descargados y decodificados: 75 frames, coincidentes con sus manifiestos.
- Consulta de eventos de la etiqueta: dos entradas tras las dos primeras fases.
- Calentamiento de modelos separado de las mediciones: 37,39 s.
- Umbral 0,91, margen 0,02, reconocimiento cada 15 frames, detección cada frame; precisión float32 `highest`.
- Entorno: Python 3.11.13, PyTorch 2.7.1+cu128, Transformers 4.44.2, RTX 5070 Ti Laptop.
- Suite del proyecto: 115 tests aprobados en 13,53 s; Ruff limpio. Un aviso externo de Starlette sobre HTTPX.

## Reproducción

Desde la raíz del repositorio, con las dependencias y pesos disponibles:

```powershell
$env:ODIN_DEVICE = 'cuda:0'
# ODIN_DETECTOR, ODIN_ENCODER y ODIN_CAPTIONER pueden apuntar a pesos locales.
python -m scripts.acceptance_video --video data/lab/source/traffic.webm --out-dir data/traffic-validation --classes car --seconds 20
```

`--out-dir` debe ser nuevo: el ensayo no reutiliza etiquetas de otra ejecución. El JSON conserva
configuración efectiva, tiempos individuales, versiones y resultado; un fallo termina con código no cero.
Los vídeos, pesos y memorias de prueba permanecen fuera de Git según `.gitignore`.

## Alcance y estado ejecutable

El código se ejecutó satisfactoriamente usando Python 3.11 y las dependencias locales disponibles.
Es una aplicación Python con comandos `odin-vision` / `python -m odin_vision`; no es un EXE autónomo.
El `.venv` de esta máquina apunta a un Python 3.13 inaccesible y no fue el entorno usado en esta prueba.

Transformers 4.44.2 está por debajo del contrato `>=4.48,<5`: falta repetir con un entorno admitido.
No se modificó ese contrato ni se activó TF32. El acceso de red para instalar dependencias está bloqueado.
El ensayo es reproducción de vídeo real por loopback, no una cámara física, RTSP o red remota.
Los frames con etiqueta prueban funcionamiento del flujo; no miden exactitud de identidad porque no hay
anotaciones de identidad independientes. El vehículo aprendido sale de la escena: no se espera su etiqueta
en todos los frames. Las cifras no constituyen una comparación de velocidad con v1 en igualdad de hardware.
